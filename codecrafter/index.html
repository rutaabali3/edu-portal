Three collaboration workflows

The tool is secondary to the workflow. Define the learning or product goal first, then choose where the code should run and how changes will be reviewed.

01

Pair in a lesson

Use a browser editor for a low-friction exercise, quick prototype, or shared explanation. Keep the project public only when its contents are safe to share.

Fast start
02

Open a real repo

Use a configured cloud environment when the project has dependencies, scripts, ports, or a team onboarding cost worth eliminating.

Reproducible setup
03

Review the change

Pairing is not a substitute for version control. Use branches, pull requests, tests, and a short README so another learner can reproduce the result.

The current shortlist

Pick the right place to code

These tools are not interchangeable. The descriptions below focus on what the official providers currently advertise and where each option fits best.

Replit

Free + paid

Browser-first app building with Agent, database, publishing, integrations, and team collaboration. Starter is free; Core and Pro add credits, collaborators, and higher limits.

Open Replit

GitHub Codespaces

Free quota

Fully configured cloud development environments native to GitHub, with browser or local IDE access, port forwarding, and repository or pull-request entry points.

Open Codespaces

StackBlitz

Public free plan

Web development environments powered by WebContainers, running Node.js inside the browser. Useful for fast front-end demos and shareable reproductions.

Open StackBlitz

GitHub + Codespaces

Free quota

For learning team practice, combine issues, branches, pull requests, Actions, and a dev-container configuration instead of only sharing a live editor.

Read the docs

Local VS Code

Free editor

Best when a learner needs full local control. Pair it with Git, a shared repository, and a consistent setup guide rather than treating the editor as the collaboration layer.

Visit VS Code

Live Share

Free extension

For local pair programming, Live Share lets collaborators work together in the same development session while keeping each person's editor and environment.

Learn about Live Share

Practical answers

Questions beginners ask

It can be enough for a prototype or a small teaching project. For a production codebase, use version control, repeatable configuration, tests, backups, and a deployment process regardless of where the editor runs.

It can mean public projects, a monthly compute quota, limited storage, limited credits, or a free editor with paid hosting. Always read the provider's current pricing page and set usage controls where available.

Never commit passwords, API keys, private data, or unreviewed secrets. Share the smallest safe reproduction, use environment variables, and make repository visibility an intentional decision.
